# 教学设计说明

这个网站不是把深度学习知识点堆成目录，而是把每个知识点做成“看得见、能调参、能复盘”的学习单元。设计目标是：即使学习者只有高中数学基础，也能先建立直觉，再慢慢进入公式、代码和工程判断。

## 学习对象

核心学习者是零基础或弱基础学生：

- 会四则运算和简单函数图像
- 不默认掌握 PyTorch
- 不默认理解矩阵、梯度、softmax、卷积、注意力
- 容易被大段源码、抽象公式和黑盒图表劝退

因此页面不先展示完整源码，而是先展示学习路径、图形变化、参数实验和三分钟讲义。

## 每节课的学习闭环

课程页固定围绕六步组织：

1. 本节主线：告诉学生先看什么、后做什么。
2. 3 分钟版：先给低门槛解释和完成标准。
3. 概念动画：把抽象过程变成可观察图形。
4. 动手实验：只改一个参数，观察读数变化。
5. 完整讲义：进入更系统的定义、原理、误区和工程意义。
6. 学习动作：我已理解、加入复习、下一节。

这个顺序避免学生一进入页面就看到源码或大段文字。

## 图文绑定原则

每段解释都尽量绑定页面中的实际元素：

- 热力图：颜色深浅代表权重或响应强度。
- 曲线：观察 loss、梯度、验证集差距。
- 节点图：观察模块边界和数据流。
- 控件：明确告诉学生调哪个参数、看哪里变化。
- 源码：只解释和当前动画/控件有关的片段。

文字的任务不是替代图，而是告诉学生“应该盯哪里”。

## 新手模式与进阶模式

课程页提供两种阅读密度：

- 新手模式：隐藏硬核笔记、LLM 接线图和完整源码，优先保证学习路径清晰。
- 进阶模式：展开源码、工程笔记和更完整的拓展内容。

这样可以避免零基础学生被专业细节压垮，同时也保留项目实践和工程深度。

## 中央控制台的教学定位

中央控制台不是单纯炫技，它承担“从知识点到模型系统”的迁移训练：

- 学完注意力机制后，进入控制台加载 Transformer mini。
- 学完 CNN 后，观察卷积、特征图和分类头的关系。
- 学完训练动态后，观察 loss、梯度和参数更新如何联动。

模型构建器特别强调 shape 诊断。初学者最常见的工程错误不是公式背错，而是张量维度对不上。控制台会把每层输入/输出 shape 展示出来，并在错误时给出修复建议。

## 复习系统

学习动作保存在浏览器本地：

- 我已理解
- 加入复习
- 今日推荐
- 弱点分析
- 错题/实验记录

当前版本以本地持久化为主，适合作为个人学习网站和实验记录本。后续如果接入账号系统，可以把这些记录迁移到后端。

## 八股文训练营

CS 面试部分不是孤立题库，而是和深度学习工程场景绑定：

- 网络：模型服务请求、延迟、重试、HTTPS
- 数据库：实验记录、索引、慢查询
- 算法：数据结构、搜索、排序、图遍历
- 操作系统：进程、线程、内存、文件系统
- 系统设计：训练平台、推理服务、缓存和队列

目标是让学生知道这些基础知识为什么会在 AI 工程里反复出现。

## 内容质量标准

每个重点章节应尽量满足：

- 有生活化类比
- 有严谨定义
- 有图中元素解释
- 有可操作控件说明
- 有误区和排查步骤
- 有工程应用场景
- 有源码对照
- 有学习完成标准

这套标准由 `scripts/quality_check.py` 和 Playwright E2E 共同守住，避免页面退回“知识点罗列”。
